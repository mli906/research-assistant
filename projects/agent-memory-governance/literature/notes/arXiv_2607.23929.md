# arXiv:2607.23929 — MemTX: Transactional Belief Commit for Stateful Agent Memory (Li et al., 2026-07-27)
Tags: mechanisms, core. Read: full text via arXiv HTML (WebFetch-assisted), 2026-09-24.

- **Problem:** A memory write is treated as immediately actionable truth. Polluted tool output, stale updates or half-finished notes from other agents can drive irreversible actions.
- **Method:** Records carry evidence, permissions (owner, roles, share scope), provenance DAG, validity interval and type. Eight lifecycle states: raw → tentative → validated → committed → action-safe, plus quarantined, superseded and revoked. Snapshot-isolated transactions with four risk tiers. A validate-and-commit pipeline (evidence threshold, validity, authority-based conflict adjudication, dependency stability). Irreversible tools are gated on belief state. Retraction triggers typed cascading repair. Invariants machine-checked over 5.5M states.
- **Data/results:** 90-case conformance suite covering six corruption families, including *permission laundering*, plus a 56-case hardened extension and a 24-episode refund pipeline. Five backbones (Qwen3-8B, Qwen2.5-14B, GLM-4.7-Flash, GPT-5.4-mini, GPT-5.5). Scores 0.756–0.956. Significant over baselines on four of five backbones and tied with a Cordon variant on the strongest. The only method with zero downstream harm on every backbone. Token overhead ≤14%.
- **Stated limitations:** protection limited to declared provenance; transcription and retry across transactions evade gating; compensation is logged, not executed; tool reversibility is static.
- **Critique:** The database-transaction framing (staging, commit, cascade repair) fits "four-eyes"/maker-checker controls in finance well. The benchmark is self-constructed and small. The refund pipeline is the closest thing to a financial workflow among the core papers.
