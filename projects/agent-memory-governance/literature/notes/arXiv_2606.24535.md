# arXiv:2606.24535 — Governed Shared Memory for Multi-Agent LLM Systems (Margalit et al., 2026-06-23)
Tags: mechanisms, core. Read: full text via arXiv HTML (WebFetch-assisted), 2026-09-24.

- **Problem:** "Fleet memory" failure modes: unauthorized leakage, stale propagation, contradiction persistence, provenance collapse.
- **Method:** Four primitives (scoped retrieval, temporal supersession, provenance tracking, policy-governed propagation), implemented in MemClaw, a *production* multi-tenant memory service with a tenant → fleet → agent hierarchy. Each object carries writer identity, timestamps, visibility scope, status and optional RDF triples. Evaluated with the ArgusFleet harness: 192 leakage probes, 200 contradiction pairs, 50 depth-4 provenance chains, 40 propagation writes.
- **Results:** Provenance 50/50 chains reconstructed (median 291 ms per hop). Fleet-sibling visibility 117/120, cross-fleet leaks 0/80 in the propagation experiment. Contradiction detection only 98/200 (49%): a synchronous near-duplicate gate rejected 206/400 writes before the contradiction detector ran. A **GET-by-id path enforced only tenant scope, not sub-tenant scope**, so an agent could read cross-fleet rows; this was disclosed and fixed. Leakage by access path: in the leakage experiment the **semantic-search path leaked on 72/164 cross-fleet probes (0.439)** because the fleet filter was only partly applied alongside similarity ranking. The propagation experiment tested direct visibility of fleet-scoped writes and found 0/80. Verified by a second, targeted fetch on 2026-09-24. The abstract's "zero cross-fleet leakage" refers only to the propagation experiment.
- **Stated limitations:** self-evaluation (authors built both system and harness); cross-tenant surface untested; no baseline; about 200 trials per experiment.
- **Critique:** A rare *production* negative-results paper. The inconsistent enforcement across API paths (search vs GET) is exactly the kind of defect that information-barrier audits in banks look for. The paper shows leakage depending on which read path is used (search leaked 44%, GET bypassed sub-tenant scope, direct propagation held). It is a strong case for testing every read path.
