# FinPerMA: event-grounded personalized-memory benchmark for financial LLM agents (arXiv:2608.04095)
Read: full text (arXiv HTML, 2026-09-24, via WebFetch extraction). Tags: finance-apps, core.

- **Problem.** Can an advisory agent keep and *update* a per-client user model over a long horizon, especially after material life/market events?
- **Data.** Synthetic: ~300 personas (276 in the eval set) calibrated to Chinese retail-investor surveys (demographics, Big Five, risk tolerance, 4 Behavioral Investor Types). 97 dated events 2020–2026 (17 macro, 64 industry, 16 personal); 5–8 per persona. Multi-session dialogues from a task-oriented user simulator. 2,994 questions (2,494 MCQ, 500 open) at 4 temporal checkpoints, including a **Post-Shock** checkpoint. Deterministic behavioural-finance impact rules + controlled LLM narration + automated screening. Frozen corpus + rule engine released (URL not stated in the text; license not stated).
- **Systems.** No-memory, full-context, BM25, BGE-M3 dense RAG, Mem0, MemOS, Memobase; 7 frontier backbones.
- **Results.** Full context 40.1–46.9% vs no memory 18.2–31.2%. Nothing exceeds ~47% overall. The full-context vs Mem0 gap widens from 8.0 pp to 13.0 pp post-shock. Dense RAG recovers ~88% of the gap at 1.4k tokens (vs 12.8k for full context). Structured memory systems recover 54–79% but discard preference signals. ~66% of errors fall into zero-memory default, single-signal over-inference and temporal misalignment.
- **Limitations (stated).** Synthetic personas; short timelines; one seed; unmatched token budgets; no real-investor validation.
- **Critique.** This is the closest existing artifact to a finance client-memory testbed, and a natural base for governance experiments. It measures only utility, not privacy, erasure, cross-client isolation or suitability-record auditability. Its Post-Shock design could be reused for **staleness** (for example, a KYC refresh after a life event). The license must be checked before reuse.
