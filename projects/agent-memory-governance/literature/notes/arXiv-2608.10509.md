# MAP-Graph: provenance-aware shared memory for multi-agent workflows (arXiv:2608.10509v1, 2026-08-11)
Read: full text (arXiv PDF, 14 pp, main text and main tables; appendices skimmed; reviewer, 2026-09-25). Tags: gaps-check, threats.

- **Mechanism.** A typed execution graph (agents, sources, memories, claims, actions; derived_from/summarized_from/invalidated_by edges). Retrieval does a **hard permission filter first** (CanRead), then reranks by semantic similarity × multiplicative path trust over recursive ancestry. A risk-indexed action-time gate returns Allow/Block/Reverify/Redact/AskUser. Derived memories get the **intersection of their referenced scopes at write time** (label propagation). Affected descendants are *marked, not deleted*, and their lineage is kept for audit. Revocation recomputes direct descendants.
- **Evaluation.** 2,700 synthetic templated tasks (corporate workflow, SWE, research assistance; groups: clean, poisoned propagation, private leakage, permission revocation, action risk, compression). Seven baselines, including adapted Collaborative Memory and MemLineage, plus a flat-metadata control. Results: TSR 94.96%, exact accuracy 72.70%, leakage 0%, revocation violations 0%, unsafe actions 1.52%. The action-risk group still has 41/450 (9.11%) impermissible Allows. Single run, Qwen2.5-7B, plus a 540-task transfer to GLM-4-9B and Llama-3.1-8B.
- **Critical limits (stated).** "Between tasks the graph and vector collection are reset, so the experiments concern **within-task coordination rather than cross-session accumulation**." It uses one four-agent round. Permission labels are given by the benchmark rather than inferred. There is no conflict/supersession state machine, no finance and no history-dependent access. Query-time CanRead does not traverse every parent. Leakage is a canary or an Allow on a private case, with no inference/aggregation probe.
- **Relevance.** GP2: it covers per-item and ancestry-propagated authorization in shared memory. It does *not* cover persistent multi-client stores, Brewer–Nash dynamics or aggregation. GP3: it covers restriction propagation through summaries (generic). GP1: its "mark, don't delete, keep lineage" pattern is another instance of restrict-and-retain. It cites "Margalit et al. 2026", a production governed shared memory, as the closest system.
