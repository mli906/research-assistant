# arXiv:2505.18279 — Collaborative Memory: Multi-User Memory Sharing in LLM Agents with Dynamic Access Control (Rezazadeh et al., Accenture, 2025-05-23)
Tags: mechanisms, core. Read: full text via arXiv HTML (WebFetch-assisted), 2026-09-24. Foundation (just before the 2025-06-01 cutoff); heavily cited forward (≥25 citing works by 2026-09 per lit.py cites).

- **Problem:** Memory work assumes a single user. Enterprises need cross-user sharing under asymmetric, time-varying permissions.
- **Method:** Two time-indexed bipartite graphs, user→agent G_UA(t) and agent→resource G_AR(t). Two memory tiers (private, shared). Each fragment carries immutable provenance (timestamp, originating user, contributing agents, accessed resources), which allows *retrospective* permission checks. A read policy projects fragments into filtered views. Write policies (private/shared) apply context-aware transformations and can be configured globally or per user, agent or time.
- **Data/results:** MultiHop-RAG (2,556 queries, 5 users, 6 agents): resource calls fall 59–61% at 75% query overlap, with accuracy around 0.90. Asymmetric scenario: 200 synthetic business queries, no ground-truth accuracy. Dynamic scenario: SciQAG, 100 queries; access matrices show policy adherence.
- **Stated limitations:** Regulatory and privacy obstacles force synthetic or benchmark data. Concurrency, large-scale role churn and LLM hallucination despite enforcement are unexplored. Cost is measured only as call counts.
- **Critique:** This is the closest prior work for *information barriers* (Chinese walls) in finance. Provenance-carrying fragments plus revocable permissions map directly onto need-to-know. However, the paper does not test leakage adversarially, and "transformations" of shared fragments (e.g., summarising private data into shared memory) are a potential laundering channel it does not measure.
