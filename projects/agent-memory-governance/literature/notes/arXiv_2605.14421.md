# arXiv:2605.14421 — MemLineage: Lineage-Guided Enforcement for LLM Agent Memory (Ouyang & Hou, 2026-05-14)
Tags: mechanisms, core (also relevant to threats). Read: full text via arXiv HTML (WebFetch-assisted), 2026-09-24.

- **Problem:** Untrusted content gets written to memory and *laundered* through LLM summarisation into trusted-looking entries, which later justify sensitive actions.
- **Method:** Six modules. (1) Canonical metadata: writer principal, source hash, trust level, parents. (2) Per-principal Ed25519 signatures over canonical CBOR. (3) RFC 6962 Merkle log with explicit tombstones. (4) Weighted derivation DAG with a "max-of-strong-edges" propagation rule (theorem: Untrusted-Path Persistence). (5) Verifier-aware retrieval. (6) Sensitive-action gate that refuses when the justification descends from an external ancestor. Three attribution options: coarse, LLM self-eval, attention-based.
- **Results:** Deterministic harness, ASR by workload (AgentPoison / MemoryGraft / Sleeper-via-derivation): no defense 1/1/1; signatures only 0/1/1; MemLineage 0/0/0. Sub-ms per-operation overhead. AgentDojo live bridge: blocks 6/6 attacker goals with banking tasks preserved. Ablation over τ×K: a deeper chain needs a lower threshold (K=5 needs τ≤0.10).
- **Stated limitations:** trusts the inference stack and keys; attention attribution needs open weights; single host; no recovery (prevention only); fallback when no strong parent exists is "Trusted".
- **Critique:** It shows that signatures alone (integrity of *who wrote*) do not give provenance of *what influenced*. The derivation DAG is the governance-relevant idea and connects directly to erasure-with-derivatives (compare arXiv:2609.04875). The evaluation is mostly a deterministic mechanism harness, so its utility cost on real tasks is under-measured.
